# Совместимость приложений
{: #app-compatibility }

Porter поддерживает API Shizuku, используемые совместимыми приложениями. Необходимость дополнительного компонента зависит от способа подключения приложения.

| Что поддерживает приложение | Что установить |
| --- | --- |
| Porter напрямую | Porter |
| Только Shizuku | Porter и Porter Compatibility; Porter заменяет Shizuku, если он установлен |
| Оба варианта с выбором службы | Porter, затем выберите Porter в приложении |

Компонент совместимости помогает существующим приложениям Shizuku найти Porter. Сам Porter запускает службу, показывает запросы разрешений и управляет доступом. Оставляйте компонент установленным, пока используете приложения, которым он нужен.

## Переход с Shizuku
{: #switch-from-shizuku }

Для приложения с прямой поддержкой Porter можно оставить Shizuku установленным. Запустите Porter, выберите его в приложении и подтвердите новый запрос. Если приложение требует перезапуска, принудительно остановите его в настройках Android и откройте снова.

Для приложения, поддерживающего только Shizuku, сборка FOSS включает подходящий APK Porter Compatibility:

1. Установите и запустите Porter. Не удаляйте Shizuku, пока не просмотрите замену.
2. Откройте **Совместимость с Shizuku** на главном экране или в **Настройках**.
3. Если Shizuku установлен, выберите **Заменить**. Подтвердите **Перейти на Porter**. Porter остановит Shizuku, заменит его приложение и автоматически перенесёт подходящие решения о доступе. Если остановить службу не удаётся, Porter предложит остановить её в Shizuku и повторить попытку.
4. Иначе выберите **Установить автоматически**.
5. Вернитесь в клиентское приложение. Подтвердите доступ, если вы не импортировали существующее решение. Если приложение по-прежнему не подключается, принудительно остановите его в настройках Android и откройте снова.

Porter автоматически импортирует решения, которые удаётся проверить по установленным приложениям и их текущему доступу. Существующие решения Porter имеют приоритет. Настройки приложения Shizuku и его сопряжение не импортируются. Если базу данных доступа не удаётся прочитать, можно продолжить и выдать разрешения приложениям заново. Porter сохраняет подходящие решения о доступе до удаления Shizuku; при ошибке установки повторите попытку или используйте **Вручную**, а затем **Импортировать сохранённые разрешения**.

Встроенная замена доступна из основного пользователя Android. Если Shizuku установлен для другого пользователя или профиля, разберитесь с той установкой отдельно. Приложения другого пользователя Porter автоматически не удаляет.

APK компонента совместимости по-прежнему доступен отдельной загрузкой из того же выпуска. Для ручной установки остановите и удалите Shizuku, установите Porter Compatibility и запустите Porter. Чтобы перенести подходящие решения о доступе, используйте встроенную замену Porter; одно лишь открытие диалога замены импорт не сохраняет. Ограничения установки на устройстве могут действовать и для встроенного установщика; действие **Вручную** открывает установщик Android.

После установки на главном экране показаны версия приложения совместимости и число установленных приложений, которые подключаются через него. Нажмите его карточку, чтобы увидеть подробности, переустановить встроенную копию или удалить её. Porter сначала пробует удалить через свою службу и открывает деинсталлятор Android, если это не удалось. Удаление прерывает работу приложений, которым нужна поддержка совместимости; приложения с прямой поддержкой Porter продолжают работать. Экран совместимости сам проверяет изменения, пока он открыт.
## Могут ли Porter и Shizuku работать одновременно?
{: #can-porter-and-shizuku-run-together }

Да. Оба приложения могут быть установлены и запущены одновременно. Приложение с выбором службы подключается к одной из них за раз.

**Porter Compatibility нельзя установить одновременно с Shizuku.** Для поддержки старых приложений он использует Android-идентификатор Shizuku. Android считает их конкурирующими установками одного приложения, а не разными приложениями. Это относится и к форкам с тем же идентификатором.

Для возврата удалите Porter Compatibility и установите Shizuku. Перезапустите клиентское приложение и разрешите доступ в Shizuku. Самостоятельный Porter можно оставить установленным.

## Приложение всё ещё просит Shizuku
{: #an-app-still-asks-for-shizuku }

В настройках старого приложения может оставаться название Shizuku, даже когда доступ предоставляет Porter. Это нормально.

Компонент поддерживает распространённые способы обнаружения Shizuku. Приложения, зависящие от конкретных экранов, внутренних компонентов или очень старых API, могут нуждаться в обновлении. Если приложение не подключается, укажите его название и версию в [сообщении об ошибке Porter](https://github.com/d4rken-org/porter/issues).
