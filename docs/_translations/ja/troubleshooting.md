# トラブルシューティング
{: #troubleshooting }

## Porter が実行されていない
{: #porter-is-not-running }

デバッグアクセスを使う場合、端末の再起動後に Porter を起動し直す必要があるのは正常です。Porter を開き、[起動方法](/setup)に従って操作してください。ワイヤレスのペア設定だけではサービスは起動しません。

## 自動起動しない
{: #automatic-start-does-not-work }

インストール後は、**起動時に開始**に頼る前に、一度手動で Porter を起動してください。デバッグ経由の起動に成功すると、以降の自動起動に必要な Android 設定への権限が付与されます。通知に `WRITE_SECURE_SETTINGS` と表示されたら、パソコン経由で起動してから再試行してください。

自動起動には、Android がデバッグアクセスを利用可能にし、Porter のバックグラウンド動作を許可する必要があります。失敗する場合は手動で起動してください。

## ワイヤレスのペア設定が完了しない
{: #wireless-pairing-does-not-finish }

- Wi-Fi 接続を維持し、ワイヤレスデバッグが有効であることを確認します。
- コードを入力できるよう、Porter の通知を許可します。求められた場合は付近のデバイスやローカルネットワークへのアクセスも許可します。
- Porter の通知にコードを入力する間、Android のコード表示ダイアログを開いたままにします。期限が切れたら新しいダイアログを開きます。
- Porter 内のダイアログでは、コード表示ダイアログのペア設定ポートを使います。ワイヤレスデバッグのメイン画面の接続ポートではありません。
- VPN やローカルネットワークの制限が検出を妨げる場合は、端末同士の通信を許可するネットワークを試します。

コードが拒否された場合は、通知で**再試行**を選びます。通知が見当たらない、または古いコードのままの場合は、Porter の**ペア設定**に戻り、**ペア設定をやり直す**を選びます。Android の古いコード表示ダイアログを閉じて新しいダイアログを開き、新しいコードを入力してください。Porter のキャッシュやアプリデータを消去する必要はありません。

Android TV では、ペア設定が成功・失敗・タイムアウトのいずれの場合も Porter が結果を表示します。失敗したときは**再試行**を選び、求められたらペア設定用のユーザー補助サービスを再度有効にします。Porter が自動的に開かないときは、アプリを開いて保存された結果を確認してください。ペア設定が成功した後も、**開始**という別の手順が必要です。

新しいペア設定は、Android のペア設定済みデバイス一覧に **Porter** として表示されます。既存の項目は、削除して再度ペア設定するまで **shizuku** のままになることがあります。表示名が変わっても保存済みの鍵を置き換える必要はなく、既存のペア設定はそのまま使えます。この表示名は、Porter のアプリ一覧に表示される Shizuku API のバッジとは別のものです。

ワイヤレスデバッグが利用できない、または不安定な場合は、[パソコンから起動](/setup#with-a-computer)してください。

## パソコンが端末を認識しない
{: #the-computer-cannot-find-the-device }

`adb devices` を実行します。`unauthorized` と表示されたら、端末のロックを解除し、デバッグ要求を許可します。何も表示されなければ、USB デバッグを確認し、データ転送対応ケーブルや別の USB ポートを試してください。メーカーの USB ドライバーが必要かどうかも確認します。

起動コマンドでファイルがないと表示された場合は、インストール済み Porter の**コマンドを表示**から最新のコマンドをコピーします。

## Porter が繰り返し停止する
{: #porter-keeps-stopping }

まず端末が再起動していないか、Android がデバッグを無効にしていないかを確認し、必要に応じて Porter を起動し直します。

端末を再起動していないのに停止する場合は、メーカーのバッテリーやバックグラウンドアプリの設定を確認し、Porter のバックグラウンド動作が制限されていれば許可してください。ネットワークの変更やメーカーによる Android の改変がデバッグアクセスに影響することがあります。

繰り返す停止を報告する際は、端末の機種、Android バージョン、起動方法、停止直前に起きたことを記載してください。

## アプリが接続できない
{: #an-app-cannot-connect }

1. Porter が実行中であることを確認します。
2. [Porter Compatibility が必要なアプリか](/compatibility)を確認します。
3. サービス選択があれば Porter を選び、Android の設定でアプリを強制停止して開き直します。
4. アプリ内で連携を有効にし、Porter の要求を許可します。
5. Porter の**アプリケーション**で対象アプリを確認し、**アプリのアクセスを許可**がオンであることを確かめます。

互換アプリを使う場合、両方の APK は同じ配布元のもので、署名証明書が一致している必要があります。互換アプリを削除すると古いクライアントは Porter を使えなくなります。

## Android が APK をインストールしない
{: #android-wont-install-an-apk }

単体の **Porter Compatibility** APK を手動でインストールする場合は、先に Shizuku を削除してください。Android が同じアプリ識別子を認識しても、署名が異なる Shizuku を互換アプリで更新することはできません。Porter の統合された置き換えでは、Shizuku の削除も行われます。

Porter 自体も、古い開発ビルドと公開リリースで署名が異なる場合があります。Android は両者の上書きインストールを許可しません。古いインストールを削除するとアプリデータも消えるため、先に設定を控えてください。希望する配布元から再インストールし、アプリを再度許可します。

## テレビのインストール警告をリモコンで選択できない
{: #a-tv-installation-warning-cannot-be-selected-with-the-remote }

Play プロテクトの警告と、その**詳細**や**インストールする**のボタンは Android のインストーラーのものです。Porter はリモコン操作時のフォーカスの挙動を変更できません。また、この警告だけでは Google が APK を検出した理由は分かりません。

APK が [Porter のリリースページ](https://github.com/d4rken-org/porter/releases)のものか確認してください。警告を読んだうえで続行する場合は、USB または Bluetooth のマウスを使うとボタンを選択できることがあります。テレビへの認可済み ADB 接続がすでにある場合は、そのパソコンからダウンロード済みの APK をインストールすることもできます。

```sh
adb -s TV_SERIAL install -r /path/to/porter-compat.apk
```

`TV_SERIAL` は `adb devices` に表示されるテレビの項目に置き換え、実際にダウンロードした APK のパスを指定します。それでも Android がインストールをブロックしたり、確認を求めたりすることがあります。この方法で Play プロテクトのボタン操作が直るわけではなく、インストールが許可される保証もありません。

インストールがブロックされたままの場合は、警告の正確な文言、テレビの機種、Android のバージョン、Porter Compatibility のバージョンを報告してください。Porter に直接対応するアプリでは、互換 APK は不要です。

## アクセスを許可しても操作に失敗する
{: #access-is-allowed-but-an-operation-still-fails }

デバッグアクセスは root より制限が多く、Android のバージョンやメーカーによる追加の制限もあります。Porter はすべてのアプリ操作を可能にするものではありません。クライアントアプリ自身の要件も確認してください。

MIUI を使う Xiaomi/POCO 端末では、開発者向けオプションに **USB デバッグ（セキュリティ設定）**という別のスイッチがある場合があります。通常の USB デバッグだけではアプリ管理操作が制限されることがあります。必要な場合は追加設定を有効にして Porter を再起動してください。名称と有無はシステムによって異なります。

一部の OPPO/OnePlus システムには、開発者向けオプションにデバッグを制限する**権限の監視**があります。無効にすると操作できる場合がありますが、メーカーの保護設定を変更することになります。これらの対処法は[オリジナルの Shizuku ガイド](https://shizuku.rikka.app/guide/setup/)に基づき、Porter を使った実機での検証はまだ行っていません。

## 実行中に表示されるバージョンが違う
{: #the-version-shown-while-running-is-different }

**設定**の**バージョン**は Porter アプリのバージョンです。サービスカードをタップすると**サービス**画面が開きます。この画面では、インストール済みアプリと実行中のサービスについて、バージョン名・バージョンコード・ビルド ID と、互換 Shizuku API のバージョンを確認できます。診断情報を共有するときは、**設定**、**ヘルプとサポート**から[デバッグログを記録](#report-a-problem)してください。API バージョンは互換性を表し、Porter のリリース番号ではありません。ビルドが異なる場合は**サービスの更新があります**と表示されます。互換性のある機能は引き続き使え、Porter を開いてもサービスは再起動しません。Android のメインユーザーでサービス画面の**サービスを更新**をタップして確定すると、実行中のサービスの権限でインストール済みのビルドが適用されます。パソコンやワイヤレスデバッグの再接続は不要です。接続中のアプリは一時的に切断されますが、権限は保持されます。置き換えに失敗した場合は、以前のサービスが動作している間に**更新を再試行**を使うか、いつもの方法でサービスを起動し直してください。

**設定**の**サービスを自動的に更新**を有効にすると、Porter アプリの更新後に、ビルドの異なるサービスが動作していないかを確認します。初期設定では無効です。Android がバックグラウンド処理を遅らせることがありますが、手動の更新ボタンはいつでも使えます。停止中のサービスは停止したままです。失敗または中断した更新は、ウォッチドッグが有効な場合も含めてホーム画面に表示されます。

## 問題を報告する
{: #report-a-problem }

Porter の設定アイコンから**ヘルプとサポート**を開きます。メールでの問い合わせ、[Discord コミュニティ](https://discord.gg/5hXXgwKNgm)、[問題の報告](https://github.com/d4rken-org/porter/issues)が利用できます。

ログを添付するには、**デバッグログを記録**を選び、問題を再現してから**記録を停止**します。問い合わせフォームで保存した記録を選ぶか、**保存したデバッグログ**から共有します。ログは共有するまで端末内に保存されます。アプリ名、端末情報、Porter を通じて実行した操作が含まれる場合があります。

次の情報を記載してください。

- Porter のバージョンと Porter Compatibility の有無。
- 端末の機種と Android バージョン。
- 起動方法：ワイヤレスデバッグ、パソコン、root。
- 問題が起きたアプリとそのバージョン。
- 行った操作、期待した結果、実際の結果。

添付前にスクリーンショットやログに個人情報がないか確認してください。ワイヤレスのペア設定コードや秘密鍵を含めないでください。
