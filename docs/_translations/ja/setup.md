# Porter のインストールと起動
{: #install-and-start-porter }

[GitHub Releases](https://github.com/d4rken-org/porter/releases) から Porter をダウンロードし、次の手順で設定してください。

## インストール
{: #install }

1. リリースの **Assets** 欄から Porter の APK をダウンロードします。ソースコードの ZIP や TAR ファイルは Android アプリではありません。
2. 端末で APK を開きます。Android から求められた場合は、ブラウザーやファイルマネージャーに、この提供元からのアプリのインストールを許可します。
3. Porter を開きます。

Porter に直接対応するアプリには Porter だけで十分です。Shizuku のみに対応するアプリでは、同じリリースの **Porter Compatibility** もインストールしてください。互換アプリは Shizuku と共存できないため、先に Shizuku をアンインストールします。対象アプリを Porter で使う間は、互換アプリを残してください。詳しくは[互換性ガイド](/compatibility)をご覧ください。

## 起動方法を選ぶ
{: #choose-how-to-start }

| お使いの端末 | 起動方法 |
| --- | --- |
| ワイヤレスデバッグに対応する Android 11 以降 | [ワイヤレスデバッグ](#wireless-debugging) |
| Android 7.0 以降とパソコン | [USB デバッグ](#with-a-computer) |
| すでに root 化済み | [Root](#root) |

## ワイヤレスデバッグ
{: #wireless-debugging }

Wi-Fi 接続と Android 11 以降が必要です。メーカーによってはワイヤレスデバッグが制限されています。利用できない場合はパソコンを使ってください。

1. Android の設定で**開発者向けオプション**を有効にします。通常は**デバイス情報**を開き、**ビルド番号**を 7 回タップします。場所は端末によって異なります。
2. 開発者向けオプションで **USB デバッグ**と**ワイヤレスデバッグ**を有効にします。ネットワークへの許可を求められたら承認します。
3. Porter のワイヤレスデバッグで起動する項目で**ペア設定**をタップします。通知を許可し、求められた場合は付近のデバイスやローカルネットワークへのアクセスも許可します。
4. Android の**ワイヤレスデバッグ**設定で**ペア設定コードによるデバイスのペア設定**をタップします。このダイアログは開いたままにします。
5. Porter のペア設定通知を展開し、Android が表示したコードを入力します。ペア設定の完了を待ちます。
6. Porter に戻り、ワイヤレスデバッグの項目で**開始**をタップします。
7. Porter が実行中と表示されることを確認します。

Porter を停止しても、Android のデバッグ設定は有効なままです。デバッグアクセスが不要になったら、開発者向けオプションで無効にできます。

通常、ペア設定は一度だけで済みます。サービスの起動は別の手順で、端末を再起動した後はもう一度起動する必要があります。Android がペア設定を忘れた場合は、これらの手順を繰り返してください。

**設定**、**起動**、**ペア設定方法**でアプリ内ダイアログを選んだ場合は、Porter のダイアログがペア設定サービスを検出するのを待ち、そこでコードを入力します。ポートを求められたら、Android のペア設定コードのダイアログにあるポートを使ってください。ワイヤレスデバッグのメイン画面にある接続ポートとは異なります。

## パソコンを使う
{: #with-a-computer }

1. Google の [Android SDK Platform-Tools](https://developer.android.com/tools/releases/platform-tools) をパソコンにインストールします。
2. Android 端末の開発者向けオプションと **USB デバッグ**を有効にします。
3. データ転送対応の USB ケーブルで接続し、端末のロックを解除してデバッグ接続を許可します。信頼できるパソコンだけを許可してください。
4. Platform-Tools フォルダーでターミナルを開き、`adb devices` を実行します。Windows PowerShell では `./adb.exe devices`、macOS や Linux で ADB が PATH にない場合は `./adb devices` を使います。
5. Porter のパソコン経由で起動する項目から**コマンドを表示**をタップし、そのコマンドをそのままパソコンで実行します。必要に応じて、前の手順に合わせて `adb` の実行ファイルの接頭部分を調整してください。
6. Porter が実行中であることを確認します。その後、ケーブルを抜いて構いません。

複数の端末が接続されている場合は、表示されたコマンドの `adb` の直後に `-s DEVICE_SERIAL` を挿入します。`adb devices` に表示される、Porter を動かす端末のシリアル番号を使ってください。

Porter を更新または再インストールした後は、コマンドを取得し直してください。パスが変わることがあります。Shizuku や別のインストールからコピーした起動コマンドは使わないでください。

## Root
{: #root }

この方法は、すでに root アクセスが使える端末向けです。Porter のインストールで端末が root 化されることはありません。

1. Porter を開き、root 起動の項目で**開始**をタップします。
2. root 管理アプリで Porter の要求を許可します。
3. Porter が実行中になり、起動モードが root であることを確認します。

root とデバッグアクセスを切り替える前に、現在の Porter サービスを停止してください。

## アプリを許可する
{: #allow-an-app }

使いたいアプリを開き、Porter または Shizuku との連携を有効にして、Porter のアクセス要求を許可します。アプリは Porter のデバッグ権限や root 権限で操作できるため、信頼できるものだけを許可してください。

アクセスを取り消すには Porter の**アプリケーション**を開き、対象アプリの許可をオフにします。Porter と Shizuku の許可設定は別々です。

すべてのアプリのアクセスを一時停止するには、この画面上部の**アプリのアクセスを許可**をオフにします。個別の許可設定は保持されます。再びオンにするとアクセスが再開します。すでに開始されたシェルコマンドは、一時停止中も実行を続ける場合があります。

アプリにサービス選択機能がある場合は Porter を選び、そのアプリの設定手順に従ってください。選択の変更後に再起動が必要なら、Android のアプリ設定で**強制停止**してから開き直します。

## Porter を停止する
{: #stop-porter }

ホーム画面の Porter が実行中であることを示すカードをタップし、**Porterを停止**を選びます。接続中のアプリは、Porter を再び起動するまでアクセスできなくなります。

## Porter を更新する
{: #update-porter }

新しい APK を既存のアプリに上書きインストールし、Porter を再び起動します。Porter Compatibility も使用している場合は、同じリリースから更新してください。Android の更新には一致する署名が必要です。拒否された場合は[インストールの問題](/troubleshooting#android-wont-install-an-apk)をご覧ください。
